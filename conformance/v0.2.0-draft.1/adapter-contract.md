# Conformance adapter contract 1

The harness starts the supplied command without a shell for every operation. It writes exactly one UTF-8 JSON line to stdin and expects exactly one JSON result on stdout, then exit status 0. Write diagnostics only to stderr. Each process has a 10-second deadline and 4 MiB output limit. Do not log private material. Implementations need only synthetic keys supplied by the test input. The harness has no runtime dependency on repository modules, npm packages, network access, or a registry.

Every input has `adapter_version:"context-layer-conformance-adapter/1"` and `operation`. Success is `{ok:true,result:...}`. Expected protocol rejection is `{ok:false,error:{code:"UPPERCASE_ERROR_CODE"}}` with exit 0. Unsupported operations return `UNSUPPORTED_OPERATION`, which is a conformance failure, not a skipped pass. Adapter crashes, malformed output, timeout, or nonzero exit are harness failures. Additional error message text is informative and ignored.

Operations:

- `validate_schema`: inputs `schema_name` (one of `context-request`, `policy-decision`, `scoped-context-bundle`, `receipt`, `memory-update-proposal`) and `value`; result `{valid:boolean}` using the included versioned core schema. This checks shape only, not local canonical-ID/semantic validity.
- `canonicalize`: input `value`; result `{canonical_json,digest}`.
- `finalize_record`: inputs `unsigned`, `id_prefix`; result finalized record.
- `purpose_code`: input `value`; result `{valid:boolean}`.
- `evaluate_policy`: inputs `request`, `policy`, `clock` (ISO timestamp), optional `approval`, `approval_verifier` (`authenticated`, `absent`, `rejected`), `receipt_preflight` (`available`, `absent`). Result full finalized decision. `authenticated` is an explicitly synthetic host attestation of this supplied approval ID and computed request/policy digests, not a bypass in production code. `absent` omits the callback; `rejected` supplies a callback returning false.
- `issue_bundle`: inputs `request`, `policy`, `claims`, `clock`, `key_id`, `synthetic_seed_hex`. Use a test receipt store with available preflight, evaluate policy, and issue with default issuer. Result full authenticated envelope. The runner independently verifies the signature with the derived public key.
- `verify_envelope`: inputs `envelope`, `clock`, `recipient`, `key_id`, `public_key_hex`, `revocation` (`clear`, `revoked`, `error`). Verify/open once using a fresh available receipt store; result `{accepted:true}`. Use only the supplied public key for default authentication. Optional `legacy_hmac:true` and `synthetic_legacy_key_hex` select the profile’s verify-only retired HMAC reader for a compatibility test; this must never enable legacy issuance or affect the false-by-default path. The named revocation modes respectively return false, true, or throw from the deployment provider.
- `memory_proposal`: the same envelope verification setup plus `proposal:{operation,proposed_claims,provenance_handles,rationale}`. Open and propose; return finalized proposal. Public direct-write validation is a separate `validate_proposal` operation with `proposal`, returning `{valid:true}` or a protocol error.
- `receipt_log`: inputs `clock`, `synthetic_seed_hex`, `operations` (two receipt operation strings). Use new local isolated storage, the receipt defaults and exact actor/subject/summary in the profile transcript. Append both receipts under authenticated anchor version 2. Return `{log_path,log_jsonl,anchor_jsonl,missing_anchor_error,rollback_error}`. `log_path` is the actual absolute resolved path string used for the D({receipt_log_path}) binding; the harness does not require identical temporary paths across OSes. Establish `missing_anchor_error` by trying to open another log without anchor configuration; establish `rollback_error` by retaining just the first log line with the newest anchor intact and reopening. The harness verifies every returned log and anchor byte/hash/signature independently. Remove temporary files before exit.
- `replay`: same inputs as `verify_envelope`, result `{first_accepted:true,second_error:"BUNDLE_REPLAY",restart_error:"BUNDLE_REPLAY"}`. Open twice with one consumer, then a fresh consumer backed by the same receipt state. It is not a substitute for filesystem concurrency testing.

Error precedence and record formats are in `profiles/local-core-0.2-draft.1.md`. A kit pass covers only the assertions actually listed in the JSON report. Schema snapshots are included for implementers; validating every conceivable schema instance, full RFC 8785 numeric coverage, durable multi-process storage, and security certification require additional evidence. The six fixture files are separate from the four manifest-bound original vector sets.

Run only adapter commands you trust: they execute with your local account permissions. Process timeout/output limits are not a sandbox, a memory quota, or descendant-process isolation. The harness kills its direct adapter process on timeout.
